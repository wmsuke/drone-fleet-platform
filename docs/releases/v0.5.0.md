# v0.5.0：OTAと段階配信

Phase 5（#164、#165〜#176）のlocalアプリOTAをまとめる。バージョン名は対象機能の区切りで、Git tagやGitHub Releaseの発行を意味しない。

## 利用できること

- Ed25519署名manifest・不変archiveの生成、登録、互換性検証とlocal配信。
- opt-inの機体別supervisor、低権限Linux子アプリ、永続journalと実bundleの切替。
- 対象・配信物・方針のsnapshot、全対象予約、1/3/残りの段階承認、永続outbox。
- DB保存receipt、challenge HEALTH、新boot/version/digestと13標本/60秒の証拠評価。
- 異常時の後続抑止、停止要求と停止確認、制限付きretry・明示rollback・回復評価。
- 必須承認と障害対応の介入/audit記録、配信・評価・停止復旧の画面。

更新受付・受領・適用・health成功を分ける。停止はrollbackではなく、旧版へ回復しても元更新を成功へ戻さない。結果不明や前試行未停止は人間判断とし、予約を保持する。

## 再現と更新

[OTAデモと更新・削除手順](../ota-demo.md)から実行する。既存の通常10台デモは維持し、OTAは既定で無効である。旧command/ACK/telemetryを維持する一方、OTAの送受信・保存receiptは対応サービスを揃える必要がある。DB migration→ingestor/API→機体別supervisor・公開鍵・baseline→観測確認→先行承認の順とし、既存stateの再bootstrapやDB downgradeは行わない。

## 検証と保証しないこと

[E2E記録](../ota-e2e.md)に10台1/3/6の実更新、異なる実bundle、backend再起動、先行失敗・rollback成功/失敗/不能・報告欠落、検証層ごとの障害条件を記す。[PR #187](https://github.com/wmsuke/drone-fleet-platform/pull/187)ではQUERYと実行中observeの競合も修正した。初回CIの更新前の承認拒否と、同コミット再実行・独立local全5件成功を区別して記録している。

対象はLinux arm64/x64・Node.js 22のsimulatorアプリだけである。Edge Agent、firmware、OS/runtime/supervisor更新、実機安全、実AWS OTA、認証/認可、無停止移行、汎用Task/KPI集計は提供しない。費用・人間の実作業時間の欠測を0へ補完しない。鍵失効・旧版欠落・非互換schema・disk/journal破損・未知の子ではrollbackできない。

設計の正は[ADR 0007](../adr/0007-ota-update-evaluation-and-recovery.md)、通信は[OTA v1](../ota-protocol.md)、KPI計画との対応は[デモの対応表](../ota-demo.md#6-kpi計画との対応と保証範囲)を参照する。
