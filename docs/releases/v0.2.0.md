# v0.2.0

v0.2.0では、Phase 1のローカル構成を維持したままAWS IoT Core経由の通信を追加した。

## 変更点

- TerraformでThing、デバイス用・telemetry-ingestor用・API用IoT Policy、証明書attachment、ATS endpoint outputを管理
- クライアント側で秘密鍵とCSRを生成し、デバイス証明書を発行・検証・失効するスクリプトを追加
- Thing name、MQTT clientId、deviceIdを一致させ、機体単位でtopicを制限
- simulator、telemetry-ingestor、APIに`local`と`aws-iot`のtransport切替を追加
- AWS経由のtelemetry・status・command・ACKと、他機体topic・無効証明書の拒否を2台で確認
- AWS環境の作成、確認、削除と費用確認の入口を文書化

## 維持する機能

`docker compose up --build -d --wait`によるローカルデモは変更せず、AWS projectや証明書なしで利用できる。MQTT topic、payload、QoS、retain、protocol検証、DB schema、HTTP API、ダッシュボードは両transportで共通である。

## 検証結果

2026年10月5日にselected Region `ap-southeast-2`で、異なる証明書の仮想ドローン2台を使って次を確認した。

- 2台のONLINEとDBへ保存されたtelemetry
- 各機体へのcommandとACKNOWLEDGED
- 他機体topicへのpublish・subscribe拒否
- `INACTIVE`証明書の接続拒否
- ローカルMosquitto経路の回帰
- 検証後のThing・証明書・Policy削除と空のTerraform state

再現手順と費用上の注意は[AWS IoT Core接続手順](../aws/README.md)、詳細な実行結果は[AWS IoT Core E2E](../aws/e2e.md)を参照する。

## 対象外

実機、AWSでの継続負荷、通信断中の永続バッファと再送、Fleet Provisioning、証明書の自動ローテーション、OTA、ROS 2連携は含まない。
