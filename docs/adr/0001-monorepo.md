# ADR 0001: pnpmでTypeScriptのモノレポを構成する

- 状態: 採用
- 決定日: 2026-09-28

## 背景

このリポジトには、API、MQTT受信処理、シミュレータ、ダッシュボードと、通信仕様やDB接続などの共通パッケージが含まれる。Phase 1以降でこれらをIssue単位で追加しつつ、型、設定、検証コマンドのずれを防ぐ必要がある。

## 決定

Node.jsとTypeScriptを共通の実行・開発基盤とし、pnpm workspaceで1つのモノレポを構成する。実行アプリは`apps`、共通パッケージは`packages`に置く。依存関係は1つの`pnpm-lock.yaml`で固定し、リポジトルートの`pnpm check`からlint、型チェック、テスト、ビルドを実行する。

## 理由

- シミュレータと受信側が同じ通信の型と検証処理をworkspace依存として参照できる。
- TypeScriptの共通設定と開発コマンドを1か所で管理できる。
- 単一のlockfileをローカルとCIで使い、依存関係の再現性を保てる。
- サービスの配置と責務を分けたまま、1つのリポジトで段階的に実装できる。

## トレードオフ

- 共通設定やlockfileの変更が複数のworkspaceに影響するため、ルートの品質チェックで全体を検証する必要がある。
- workspace間の依存を増やしすぎると責務の境界が曖昧になるため、共通化は`protocol`、`database`、`config`の明確な用途に限定する。
- サービスごとの独立したバージョン管理やリリース方法は現時点で定めない。必要になったPhaseで追加する。
