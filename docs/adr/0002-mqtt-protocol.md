# ADR 0002: デバイスとの通信にMQTTを使う

- 状態: 採用
- 決定日: 2026-09-28

## 背景

仮想ドローンから定期的にテレメトリと接続状態を送信し、基盤から対象機体へコマンドを送る。デバイスの予期しない切断を扱い、ローカル構成を維持したまま後続PhaseでAWS IoT Coreへ接続先を拡張する必要がある。

## 決定

デバイスとFleet Platformの双方向通信にMQTTを使う。ローカル開発ではEclipse Mosquittoを使い、Phase 2でAWS IoT Coreへの接続経路を追加する。トピック、QoS、retain、メッセージ形式は[通信仕様](../protocol.md)で定める。ダッシュボードはMQTTに直接接続せず、HTTP APIを使う。

## 理由

- publish/subscribeにより、デバイスと受信・コマンド送信処理を分離できる。
- LWTとretainを使って接続状態を通知できる。通知だけに依存せず、サーバーの最終受信時刻もオンライン判定に使う。
- QoSをメッセージの用途ごとに選び、テレメトリの欠損許容とコマンド・ACKの配信を分けて扱える。
- MosquittoとAWS IoT Coreで共通の通信仕様を使う方針により、AWS対応後もローカル構成を残せる。

## トレードオフ

- QoS 1は重複配信があり得る。Phase 1では、コマンドの重複実行をプロセスの稼働中に限り`commandId`で防ぐ。再起動後も防ぐための永続化と、テレメトリの永続的な重複排除はPhase 3で扱う。
- MQTTの送信成功はデバイスでの操作完了を意味しない。ブローカーへの送信、ACKによる受領、実行完了を別の状態として扱う。
- Phase 1ではオフライン中のデータ保存、永続セッション、コマンドの自動再送を実装しない。通信断対応はPhase 3で追加する。
- Phase 0のMosquittoはローカル開発に限って匿名接続を許可する。実環境の個体認証と権限制御はPhase 2で追加する。
