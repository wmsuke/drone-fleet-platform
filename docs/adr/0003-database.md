# ADR 0003: 初期の保存先にPostgreSQLを使う

- 状態: 採用
- 決定日: 2026-09-28

## 背景

Phase 1では、デバイス情報、時系列のテレメトリ、コマンドとACKの状態を保存する。APIとMQTT受信処理が同じデータを利用し、デバイス一覧、履歴、コマンドの状態遷移を一貫して扱う必要がある。ローカルだけで再現できる構成も維持する。

## 決定

Phase 1の初期保存先にPostgreSQLを使う。`devices`、`telemetry`、`commands`の3テーブルから始め、スキーマ、接続処理、マイグレーションは`packages/database`に置く。ORMとマイグレーションにはDrizzle ORMを導入する予定だが、依存ライブラリと具体的なスキーマはDB実装時に確定する。

## 理由

- デバイス、テレメトリ、コマンドの関連をリレーショナルなスキーマと制約で表現できる。
- コマンドの作成と状態更新など、整合性が必要なDB内の処理にトランザクションを使える。
- デバイス一覧と最新状態、期間を指定したテレメトリ、コマンド履歴を1つの保存先から取得できる。
- Docker Composeに追加することで、AWSアカウントに依存せずローカル構成を再現できる。

## トレードオフ

- PostgreSQLの起動、マイグレーション、バックアップなどの運用が必要になる。Phase 1ではローカル開発に必要な起動と初期化から整備する。
- テレメトリ量の増加に合わせた保持期間、パーティション、集約、別の保存先は初期範囲に含めない。負荷と運用要件が明らかになった時点で判断する。
- DBへの保存とMQTT送信は単一のトランザクションにならない。送信失敗、ACKのタイムアウト、先行したACKの状態遷移をアプリケーション側で扱う。
